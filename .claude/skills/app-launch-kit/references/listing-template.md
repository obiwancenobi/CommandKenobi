# Google Play listing copy (en-US)

Limits are hard; the console truncates silently. Count characters before pasting.

## Title (30 max)

`<App>: <3-word hook>` — brand first, primary keyword second. No emoji, no ALL CAPS, no "free"/"best".

## Short description (80 max)

One sentence. Outcome + two features + the trust line. This is the only copy most people read.

## Full description (4000 max)

Structure that has worked:

1. One-line hook that restates the positioning. No throat-clearing.
2. Two-sentence "what it is" paragraph with the concrete nouns people search for.
3. Emoji-headed feature blocks (`🧠 SECTION` then `• bullet` lines, 3-5 bullets each). One block per tab/screen.
4. Privacy block (`🔒`): what leaves the device (ideally nothing), what permissions and why.
5. Price block (`🆓`): free / ads / IAP, stated plainly.
6. Permission disclosure line if the app needs a sensitive one (usage access, accessibility, location).
7. Closing "Perfect for anyone who wants …" sentence stuffed with the long-tail keywords.

Rules: sentences under 20 words, no hedging, no competitor names, no "#1" claims, no store badges in text.

**Scope every claim to where it is true.** An ad-funded app never gets a bare "NO ADS" / "AD-FREE" label, a
freemium app never gets "FREE FOREVER", an app with analytics never gets "NO TRACKING". Bind the claim to its
scope in the same phrase ("ads pause while you focus", "free, no Pro tier"). Grep every pill, headline, and
social line for the unscoped version before shipping; Play review and Reddit both check.

## Bahasa Indonesia listing (`store/copy/listing-id.md`)

Write it in everyday spoken Indonesian, never formal "bahasa baku": "kamu" register with nggak, udah, aja, buat, bakal; verbs like pamerin, benerin. No "lo/gue" unless asked. Keep product names, feature names and English UI labels as the app shows them. Reuse the app's own ARB terms. Same character limits as English; count them.

## What's new (500 max)

"First release." + one sentence of features + the privacy line.

## Store settings

- Category (+ alternative). Tags (5).
- Contains ads: yes/no. In-app purchases: yes/no.
- Target audience: 13+ unless the product is for kids. Under-13 triggers Families Policy (no personalised ads).
